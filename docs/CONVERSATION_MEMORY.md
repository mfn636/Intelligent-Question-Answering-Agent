# 会话摘要

2026-09-27：第一版已实现，用于补足较早对话的有效信息。

2026-10-10：入口分流已接入。只有本轮进入 ReAct 时才尝试摘要，直接回复和固定工作流不会为了整理历史额外调用模型；此前积累的原文保留到下一次进入 ReAct。路由只读取最近十条原文与当前输入，不使用摘要推断商品编号。

## 保存范围

每个 `ConversationRunner` 持有自己的 `ConversationHistory`：

- `summary`：较早完整问答的增量摘要。
- `messages`：尚未压缩的用户消息与助手最终回答。

摘要只在当前会话对象内存中保存。新建会话（即使使用相同的 `session_id`）不会恢复旧摘要，重启后也不会保留。
当前没有跨会话用户画像、会话文件归档或向量记忆检索。

## 何时生成

`ConversationRunner` 使用两个消息条数参数：

| 参数 | 默认值 | 含义 |
|---|---|---|
| `SUMMARY_TRIGGER` | 20 | 本轮进入 ReAct 且加入当前输入后原文超过此数，才尝试生成摘要 |
| `WINDOW` | 10 | 摘要成功后，保留的近期原文条数上限，包含当前用户输入 |

两个数均按消息计数，一问一答通常是两条消息。压缩边界位于完整回答之后、下一条用户消息之前，因此实际保留条数可能小于 10。
持续走 ReAct 时，首次正常触发发生在第 11 次用户输入：原文共 21 条，将前 6 轮（12 条）加入摘要，保留后 4 轮问答及当前输入（9 条）。快捷路径会延后触发。
接下来正常完成问答时，每新增约 6 轮再次摘要。

尚未达到触发阈值时，所有未压缩原文都会发送给模型，不再从中硬切最后 10 条。
这样在两次摘要之间不会出现信息空档，也避免窗口满后每轮增加一次摘要请求。

## 数据流

1. `runner.run()` 记录用量起点，将当前用户输入加入历史，创建本轮 `AgentState`。
2. Router 选择本轮路径。只有 ReAct 路径调用 `history.compact()`，选出要移出的完整问答，将旧摘要与这些问答交给摘要器；其他路径直接执行并统一记录最终回答。
3. `ConversationSummarizer` 使用注入的 LLM，按 `prompts/memory.py` 中的规则生成更新后的摘要。
4. 新摘要有效时，历史容器更新 `summary` 并删除已被摘要覆盖的原文。
5. `runner` 组装上下文：系统提示词 + 早期摘要 + 全部未压缩原文。
6. `ReActExecutor` 继续使用 `state.messages` 执行模型与工具循环。
7. `runner` 保存最终回答，汇总包括摘要调用在内的本轮用量。

摘要作为 `role="assistant"` 的历史背景加入上下文，不作为新的系统指令，也不写入近期问答、最终回复或工具轨迹。
组装时复制原文字典，工具往返只进入本轮状态，不进入会话摘要的原始消息列表。

`AgentState` 仍只负责本轮运行。`bootstrap.build_agent()` 创建摘要器并注入 Runner，摘要器与 ReAct 默认共享同一个模型客户端。
直接创建 `ConversationRunner` 时需显式传入 `summarizer`，便于测试或替换摘要实现。

## 摘要内容与更新

摘要提示词要求保留用户明确提出的需求、偏好、约束、候选对象及 ID、确认的决定和待解决问题。
用户的后续修改与取消应覆盖旧约束；一次购物预算不应被记成永久偏好。
助手建议与用户确认需要区分，价格、库存和优惠等变化信息不保存具体值，需要时重新查工具。

增量摘要仅消费旧摘要和新移出的问答，当前问题与近期原文仍直接交给回答模型。
因此用户刚修改条件时，近期原文可能暂时与旧摘要不同；上下文说明明确要求以后续用户新要求为准。
后续该轮进入摘要时再更新旧摘要。

模型被要求控制在 1500 字符内；空白、非文本、工具调用或超过 2000 字符的响应会被判为摘要失败。
代码不会强行截断过长摘要，也不会把格式校验通过当成事实准确性的证明。

## 失败与容量边界

摘要失败时，旧摘要和待压缩原文保持不变，记录警告，本轮使用它们继续回答；下轮仍超阈值时再尝试。
摘要成功、后续回答失败时，已提交的摘要仍然保留，当前用户问题也仍在原文中。
若历史中没有合适的完整问答边界，也保留原文。

持续走 ReAct 且摘要正常成功时，近期历史维持在约 10～20 条，摘要不超过 2000 字符。
这是按条数进行的容量管理，不是 token 上限：单条消息仍可能很长，工具结果也不受该窗口约束。
持续摘要失败、持续没有最终回答或连续只走快捷路径时，原文会继续积累，以免静默丢信息；token 预算、离线原文归档和硬上限另行设计。

摘要是有损压缩，生成成功后被覆盖的原文会从历史中释放，本功能不提供完整会话归档。
摘要规则依赖模型执行，可能遗漏或错误概括，真实的长对话效果还需使用目标模型评估。

## 验证

```bash
python -m unittest discover -s tests -v
```

14 项离线测试覆盖完整问答边界、触发节奏、旧摘要与新原文的增量组合、摘要失败保护及恢复、上下文角色、最新输入保留、用量统计、会话隔离和 100 轮正常对话的原文容量。
测试使用模型替身验证机制，不证明真实模型的摘要质量。未调用外部模型或向量服务。
